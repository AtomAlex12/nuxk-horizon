# nuxk Horizon

Обход блокировок на роутерах **Keenetic + Entware**: у каждого сайта свой путь —
**DPI** (nfqws2), **WARP** (Cloudflare) или **ваш VLESS-сервер** (xray), — и одна
понятная панель, в которой видно, что работает и почему сайт не открывается.

- **Три пути, три списка.** Домены раскладываются по спискам DPI / WARP / VLESS, а
  маршрутизацию делает сам Keenetic (его маршрутизация по доменам). nuxk трогает только
  свои объекты `nuxk-*` и по умолчанию работает в режиме плана: показывает, что сделал бы.
- **Проба по вашим сайтам.** Роутер регулярно открывает ваши сайты и говорит, где
  обрывается: блокировка по имени (нужна стратегия nfqws2) или по IP (нужен туннель).
- **Подбор стратегий nfqws2** (полная версия) — прогоны на Raspberry Pi и применение
  найденной стратегии на роутере кнопкой, с копией конфига и откатом.
- **Защищённый DNS** (бета) — провайдер не подменит ответы DNS: роутер спрашивает nuxk, а
  nuxk — серверы DoH через туннель. Кэш ответов: при сбое туннеля nuxk отдаёт последний
  известный адрес. И проверка, подменяет ли провайдер DNS сейчас.
- **Вход** — на роутере `root` и пароль Entware; на Pi — свой пароль администратора.

## Установка

### Что выбрать

| | **Лайт** | **Фул** |
|---|---|---|
| Что нужно | только роутер Keenetic | роутер + Raspberry Pi 4/5 (или любой 64-битный Linux с Docker) |
| Панель | на роутере: `http://<роутер>:4141` | на Pi: `http://<pi>:4200` — плюс час истории графиков, подбор стратегий nfqws2, плагины |
| Где запускать установщик | на роутере, по SSH | на Pi — он сам поставит лайт и на роутер |

**Не уверены — берите лайт.** Перейти на фул можно в любой момент: установщик фул
подхватит уже стоящий на роутере лайт.

Установщики ничего не собирают: берут готовые файлы из
[релиза на GitHub](https://github.com/AtomAlex12/nuxk-horizon/releases/latest), сверяют
каждый с `SHA256SUMS` и сам `SHA256SUMS` — с [подписью релиза](#подпись-релизов). На
роутере ничего не меняется без вашего ответа «да», а маршрутизация списков по умолчанию
выключена — nuxk только показывает, что сделал бы.

### Шаг 1. Подготовить роутер (один раз)

1. **Компоненты Keenetic.** Веб-интерфейс роутера → «Управление → Параметры системы →
   Изменить набор компонентов» → включите **«Поддержка открытых пакетов OPKG»** и
   **«Модули ядра подсистемы Netfilter»** (без них не заработает nfqws2), сохраните —
   роутер перезагрузится.
2. **Entware** — на USB-накопитель или во внутреннюю память, по
   [инструкции Keenetic](https://help.keenetic.com/hc/ru/articles/360021214160).
3. **Время.** «Управление → Параметры системы → Дата и время» — синхронизация по NTP
   (без точного времени не работает HTTPS).
4. **Войдите по SSH именно в Entware** (с компьютера в той же сети):

   ```sh
   ssh root@192.168.1.1 -p 222
   ```

   Адрес — ваш роутер (по умолчанию `192.168.1.1`); порт Entware — `222`, если у
   Keenetic включён свой SSH, иначе `22`. Пароль по умолчанию — `keenetic`: сразу
   смените его командой `passwd`. Проверка, что вы в Entware: команда `opkg --version`
   отвечает. Если видите приглашение `(config)>` — это консоль Keenetic, а не Entware.

### Шаг 2а. Лайт — на роутере

В SSH-сессии Entware из шага 1, по очереди:

```sh
opkg update && opkg install curl ca-certificates
curl -fsSLo /opt/tmp/nuxk-lite.sh https://github.com/AtomAlex12/nuxk-horizon/releases/latest/download/nuxk-lite.sh
sh /opt/tmp/nuxk-lite.sh
```

Установщик:

1. проверит роутер (Entware, архитектура, место, модули Netfilter) и покажет план;
2. спросит, ставить ли **nfqws2** (обход DPI — основа, по умолчанию «да»), **WARP** и
   **VLESS** (по желанию: они создают интерфейс в Keenetic и сохраняют его конфигурацию;
   VLESS нужен свой сервер, например 3x-ui);
3. поставит, запустит и проверит, что агент отвечает, — и покажет адрес панели.

Откройте панель: `http://<роутер>:4141`, вход — `root` и пароль Entware.

### Шаг 2б. Фул — на Raspberry Pi

1. **Docker на Pi** (если ещё нет) — и перелогиньтесь после второй команды:

   ```sh
   curl -fsSL https://get.docker.com | sh
   sudo usermod -aG docker $USER
   ```

2. **Установщик** — на Pi:

   ```sh
   curl -fsSLo nuxk-full.sh https://github.com/AtomAlex12/nuxk-horizon/releases/latest/download/nuxk-full.sh
   sh nuxk-full.sh
   ```

   Он запустит контроллер (готовый образ с `ghcr.io`) и предложит сразу поставить nuxk
   на роутер: спросит адрес роутера и порт SSH Entware, а пароль Entware вы введёте
   самому `ssh` — скрипт его не видит. Дальше — те же вопросы, что в шаге 2а.
3. **Панель:** `http://<pi>:4200`. Мастер попросит придумать пароль администратора и
   подключит роутер (`root` и пароль Entware — один раз, чтобы получить ключ доступа;
   сам пароль не сохраняется).

### Шаг 3. Первые шаги в панели

1. **«Списки»** — добавьте домены: в «DPI» — то, что открывается через обход DPI, в
   «WARP» и «VLESS» — то, что должно идти через туннель. Список «DPI» при установке
   заполняется из списка nfqws2, если он был.
2. **Сервер VLESS** (если ставили) — «xray (VLESS)» → ссылка `vless://` или подписка 3x-ui.
3. **Включить маршрутизацию.** Пока она выключена, «Списки» показывают план — что nuxk
   сделал бы. Когда план устраивает: в `/opt/etc/nuxk/nuxk.conf` на роутере поставьте
   `PLANE_APPLY="1"` и выполните `/opt/etc/init.d/S99nuxk-core restart`.

Каждый этап с проверкой и откатом — в [`docs/BETA.md`](docs/BETA.md).

### Команды, обновления, удаление

На роутере остаётся команда `nuxk`:

| | |
|---|---|
| `nuxk` | состояние nuxk и движков |
| `nuxk update` | обновиться до последнего релиза (то же делает кнопка в панели) |
| `nuxk rollback` | вернуть версию, стоявшую до последнего обновления |
| `nuxk warp` · `nuxk vless` | добавить WARP или VLESS |
| `nuxk uninstall` | удалить nuxk; настройки Keenetic остаются, конфиг и списки — в `/opt/etc/nuxk.removed` |

**Обновления роутера — кнопкой.** Раз в сутки роутер смотрит, нет ли нового релиза;
если есть — в шапке панели «доступна X», в «Система → Обновления» — что нового и кнопка.
Обновление проверяет подпись релиза, перезапускает агент на несколько секунд (обход и
туннели работают дальше) и, если новая версия не ответила, само возвращает прежнюю.

**Pi** обновляется командой — контроллер работает в Docker и не может заменить сам себя:

```sh
sh ~/nuxk/nuxk-full.sh update
```

Там же: `sh ~/nuxk/nuxk-full.sh status`, `router` (поставить или обновить nuxk на роутере),
`uninstall` (с данными — `uninstall --purge`).

### Если что-то пошло не так

| Что видно | Что сделать |
|---|---|
| `opkg: not found` или приглашение `(config)>` | вы не в Entware: войдите по SSH на порт Entware (шаг 1.4) |
| `curl: (60) SSL certificate problem` | включите синхронизацию времени (шаг 1.3) и `opkg install ca-certificates` |
| `curl: (22) … 404` | команда оборвалась при копировании — вставьте её одной строкой |
| «! Модули Netfilter» в плане установщика | включите компонент «Модули ядра подсистемы Netfilter» (шаг 1.1) |
| панель не открывается | `nuxk` на роутере покажет, что не работает; журнал — `tail -50 /opt/var/log/nuxk-core.log` |
| после обновления что-то не так | `nuxk rollback` — вернётся прежняя версия |
| какой-то сайт перестал открываться | остановите nfqws2 в панели или `/opt/etc/init.d/S51nfqws2 stop` и напишите в issues |

### Подпись релизов

`SHA256SUMS` каждого релиза подписан ключом nuxk Horizon при сборке на GitHub, и в нём
же — точный отпечаток образа контроллера. Обновление на роутере проверяет подпись ещё
старым, уже работающим агентом: подменённый релиз не встанет. Проверить релиз вручную
(OpenSSH 8.1+; файл `allowed_signers` — в `nuxk-core/internal/release/`):

```sh
ssh-keygen -Y verify -f allowed_signers -I release@nuxk-horizon -n nuxk-release -s SHA256SUMS.sig < SHA256SUMS
sha256sum -c SHA256SUMS
```

Отпечаток ключа: `SHA256:T2omf5hHIbtKjT4l5WOoKb4dj2syNWjHDDy+5j1xSr4`.

## Как это устроено

```
 Pi: nuxk-controller (фул)              роутер: nuxk-core — агент
 ├ полный веб, история графиков         ├ движки nfqws2 / usque (WARP) / xray (VLESS)
 ├ плагины (подбор стратегий — GP)      ├ списки DPI / WARP / VLESS
 └ клиент агента ── REST + ключ ──────► │  → маршрутизация Keenetic по доменам (RCI)
                   ◄── события SSE ──── └ /api/v1 (OpenAPI) + лёгкий веб
```

Контракт между ними — [`nuxk-core/api/openapi.yaml`](nuxk-core/api/openapi.yaml): в CI
проверяется, что спецификация совпадает с маршрутами агента, а типы для веба
генерируются из неё. Роутер работает и без Pi: списки и намерения хранятся на нём.

| Каталог | Что |
|---|---|
| `nuxk-core/` | агент на роутере (Go, только stdlib, один бинарник на архитектуру) |
| `nuxk-controller/` | контроллер на Pi: полный веб, история, прокси к агенту, хост плагинов |
| `nuxk-web/` | веб (Svelte 5 + Vite) — сборки `full` и `lite` |
| `engines/` | адаптеры движков: nfqws2 (над штатным nfqws2-keenetic), usque (форк usque-keenetic), xray (свой init-скрипт) |
| `install/` | установщики: `nuxk-lite.sh` (роутер), `nuxk-full.sh` (Pi) |
| `deploy/` | Docker: образ контроллера для релиза, стенд разработки на Pi, мок-стек |

Ядра движков (`nfqws2`, `usque`, `xray-core`) берутся из их релизов с закреплённой
версией, не форкаются.

## Разработка

```sh
cd nuxk-core && go run . -config testdata/nuxk.conf -debug   # агент с мок-движками, :4141
cd nuxk-web  && npm install && npm run dev                   # веб :5173, /api → :4141
make check                                                   # всё, что гоняет CI
```

`http://localhost:5173` — карточки движков, запуск и остановка, сервер xray (ссылка
`vless://` или подписка 3x-ui). `echo down > nuxk-core/testdata/mock.state` роняет
туннель usque, `mock.xray.state` — xray.

- **Стенд на Pi** из исходников (настоящие usque и nfqws2 в контейнере + контроллер):
  `sh deploy/pi/bootstrap.sh`, этапы — в `deploy/proto/docker-compose.yml`.
- **Установщики** проверяются на имитации роутера: `sh install/lite_test.sh`
  (`SH="busybox sh"` — как на роутере).

### Версии и релизы

- Версия — только в [`VERSION`](VERSION) (SemVer); `scripts/version.sh set X.Y.Z`
  поднимает её и в `nuxk-web/package.json`; изменения — в [`CHANGELOG.md`](CHANGELOG.md).
- Тег `vX.Y.Z` на `main` → GitHub Actions: `make check`, `make release` (всё, что
  скачивают установщики, и `SHA256SUMS`), образ контроллера на `ghcr.io` под arm64 и
  amd64, его отпечаток — в релиз, `SHA256SUMS` подписывается ключом из секрета
  `NUXK_SIGNING_KEY` (без него релиз не соберётся). Тег с `-` — предварительный релиз.
- Форк со своими релизами: свой ключ (`ssh-keygen -t ed25519`) — открытую часть в
  `nuxk-core/internal/release/allowed_signers` и `install/nuxk-full.sh`, закрытую — в
  секрет `NUXK_SIGNING_KEY`.
